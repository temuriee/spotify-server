### 🍭 The Problem (Before)

In Express, if you write a route with **async/await**, and something goes wrong inside it, Express doesn’t automatically catch the error. Example:

```js
app.get("/user/:id", async (req, res) => {
  const user = await User.findById(req.params.id); // 🚨 if DB fails, boom!
  res.json(user);
});
```

If the database fails, the app **crashes** 💥 because Express doesn’t know how to handle that rejected promise.

---

### 🍭 The Fix Without Library

Normally, you have to wrap everything in a big `try...catch` block:

```js
app.get("/user/:id", async (req, res, next) => {
  try {
    const user = await User.findById(req.params.id);
    res.json(user);
  } catch (err) {
    next(err); // 👈 send error to global handler
  }
});
```

That works, but you have to write `try/catch` for **every route**.
😫 It’s boring, repetitive, and easy to forget.

---

### 🍭 The Library: `express-async-handler`

This little helper **automatically wraps your async functions** in `try/catch`.

So instead of writing a lot of boilerplate, you just do:

```js
const asyncHandler = require("express-async-handler");

app.get(
  "/user/:id",
  asyncHandler(async (req, res) => {
    const user = await User.findById(req.params.id);
    res.json(user);
  })
);
```

Now, if something breaks inside (`await User.findById` fails), the library **catches the error and passes it to your global error handler** automatically.

---

### ✨ Before vs After

- **Before:**

  - You need `try/catch` in every route.
  - Easy to forget → app crashes.

- **After (`express-async-handler`):**

  - No `try/catch` needed in each route.
  - Cleaner, shorter, safer code.
  - Errors always go to your **error middleware**.

---

### 🎁 Why it’s necessary

- Saves you from writing **repetitive try/catch** everywhere.
- Makes sure your app **never crashes silently** from async errors.
- Keeps code **clean and readable**.
